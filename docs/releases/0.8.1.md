# Irelia Companion 0.8.1

Patch memory, archiving and cache trimming are now simple on / off switches that look like the rest of the app. This release also fixes what an audit of 0.8.0 found and cuts memory use: about a third less while **Evaluate builds** runs, and half the memory for the draft model kept between builds.

## Switches instead of buttons
Every on / off setting is now the same switch: what it does on the left, the switch on the right. Settings' desktop options use it too.
- **Patch memory** (Data → Draft model) is two switches:
  - **Patch memory:** on or off. Moving it makes the choice yours.
  - **Follow the evaluation** (on by default): patch memory turns on only when Evaluate builds finds it better. Switch it back on to hand the choice back.
- **Archive patches older than the window** (Data → Patches): one switch instead of Archive and Restore buttons.
  - On: older matches are compressed into the archive now, and again whenever a patch leaves the six-patch window.
  - Off: everything archived is put back.
  - If you archived with 0.8.0, it shows as on.
- **Keep the API cache to the six-patch window** (Settings → Storage): replaces the one-time button. It deletes cached matches and timelines of older patches now, and again whenever the window moves, so the cache stops growing.
- **Delete games of old patches** moved to Settings → Storage → Clean up, next to the other actions that delete, with the same confirmation.
- Segmented buttons of three or more now join up properly.

## Fixes (from an audit of 0.8.0)
- **Your games** loaded slowly with patch memory on: for every game, it re-read Data Dragon's full list of versions.
- **Matchup facts, Your games and the best buy for your gold** went by the patch memory switch rather than by the model actually built. Right after you switched patch memory off, they could include older patches' games until the rebuild finished.
- **Switching patch memory, or an evaluation changing it,** during champ select or a game now rebuilds the model as soon as the game ends. Before, it could wait up to five more minutes.
- **Restoring the archive** keeps a match in the archive if it could not be put back, instead of losing it.

## Memory
Measured on 4,400 stored games (test data). The figures are for the app's background process, which holds the data, the model and fetching. The evaluation reports are unchanged to the last digit.

| | 0.8.0 | 0.8.1 |
|---|---|---|
| While **Evaluate builds** runs (peak) | 590–660 MB | about 415 MB |
| Idle, once settled | about 200–210 MB | about 170–180 MB |
| Draft model kept in memory | 27 MB (54 MB with patch memory) | 14 MB (27 MB with patch memory) |

- **Garbage:** most of the old evaluation peak was memory waiting to be reclaimed. The evaluation now cleans up before each step, and the model after each rebuild.
- **Reading the games:** the evaluation reads the stored games one at a time and lets go of each raw timeline once the game is prepared. It no longer holds them all at once.
- **Best buy:** the best buy for your gold keeps one number per minute of each stored game instead of the whole game state (13 times smaller), with the same answers.
- **Speed:** the evaluation is also about 10 % faster.

## After installing
Nothing to do. Your patch memory choice, and an archive made with 0.8.0, carry over.
