## Why evaluations were slow on a large pool
- In the app, every thread shares one 4 GB block of memory for its scripts: fetching, the model and every evaluation thread together. That's a fixed limit of the JavaScript engine, whatever memory your PC has.
- At 170,000+ games, the model alone holds a large part of it, and each evaluation thread needs 1–2.5 GB. So an evaluation ran on 1 or 2 threads. On a 16-thread PC with 63 GB of memory, the log showed `threads: 1 … -0.6 GB of shared heap left`.

## Now
- **The evaluation runs as a process of its own, and its helpers are processes too.** Each process has its own 4 GB, so the number of helpers is limited only by your processor's threads and your free memory, with the same 15 % reserve as before.
- **Same results:** the evaluation's games are shared out and the results put back in order exactly as before. The tests check the report is the same to the last digit, also when a helper process ends partway through.
- **The log says so:** `[eval] processes: N (…, each with a heap of its own)`, and when it ends, `[eval] time: …` with its three longest steps.
- **Champ select or a game** stops the helper processes as it stopped the helper threads, so their memory goes back to the game. The evaluation finishes on its own process.
- **If the processes can't start,** the evaluation uses threads as before: helpers that don't start are replaced by threads, and an evaluation process that ends before it begins is started again as a thread. The log says so.
- **Use GPU:** only the evaluation's own process uses the graphics card; the helper processes compute on the processor.

## The progress no longer stands still
- Steps that rebuild each fold's models show what they're doing beside the step: for example **Fine-tuning on 939 new held-out games · fold 3 of 5: building its models**.
- Before, the bar stood still for those minutes and the time left kept growing. The bar itself still moves as games are measured.

## Also
- How much faster depends on your processor and pool. Each helper process holds its own copy of the evaluation's data (about 1–2.5 GB at 170,000 games), so the free memory sets how many run. Your report's **Time by step** and the log's `[eval] processes:` line show what it did.
- As with every new version, your first evaluation after installing is a full one.
- Data and policy are unchanged: Riot API and Data Dragon only, nothing leaves your PC unless you choose a backup folder, and no new dependencies or schema changes.
