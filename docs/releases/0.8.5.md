## Fix: "database is locked"
- **What happened:** fetching and the rest of the app use the database at the same time.
  - Some of fetching's writes first read, then write: queueing a pilot's match history, and looking for your own new games.
  - When the app wrote to the database in between, SQLite refused the write at once with "database is locked", without waiting. That happened while it archived or restored old patches, deleted them, or logged the builds it showed you.
  - Nothing was lost: the history or games were picked up again on the next pass.
- **Why it stayed on screen:** one such error stayed under Start fetching until you pressed Start again, even though fetching carried on. It also stayed after the own-games check that runs after your games.
- **Now:**
  - **Every write takes the database's write lock first**, and waits for it if another part of the app holds it: up to 30 s for fetching, 5 s for the rest of the app.
  - **Archiving and restoring old patches** pause 150 ms after every 200 matches, so fetching's writes get in between. On a large folder this makes archiving a few seconds slower.
  - **Fetching, the model and the evaluation** no longer write to the database when they start. Only the main part of the app sets up the database.
  - **If an error does show**, it goes once fetching (or the own-games check) works again.
- **Tested:** a writer in its own thread, shaped like fetching, ran while the archive switch archived and restored 1,200 matches, and while they were deleted. It got no error, where 0.8.4's code failed the same test with "database is locked".

## After installing
Nothing to do. The message is gone after the update; if fetching was stopped, press Start fetching as usual.
