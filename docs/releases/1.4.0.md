# Build Fetcher 1.4.0

**1.4.0 adds extra Riot API keys (a proof of concept, for testing): each key keeps its own rate limits, and together
they give fetching a larger budget.**

The installer is per user, with no admin rights. It installs over any earlier version and keeps your settings, key,
games and model in `%APPDATA%\build-fetcher\`. It isn't code-signed yet, so Windows SmartScreen warns on first run:
choose **More info → Run anyway**.

## New
- **Extra API keys (Settings → Riot API key).** The card now lists the **API keys in use** (masked, main key first)
  and has an **Add Extra API Key** button. There is no limit to how many keys can be added; each extra key has a
  **Remove** button.
  - Each key gets its own rate limiter per Riot host, so each keeps to its own budget. Every request goes to the key
    with the least work queued for that host.
  - With more than one key, each fetcher lane fetches that many games at once (one per key) and stores them in order.
  - A key Riot refuses (401 / 403) is set aside and the other keys carry on. Fetching stops with "key rejected" only
    when every key is refused. Adding or removing a key gives every key a fresh chance.
  - The Fetching page's budget meters add the keys up ("20:1,100:120 × 3 keys").
  - Extra keys are stored in `settings.json` as `riotExtraApiKeys` and, like the main key, are only ever shown masked.
    Backups still carry only the main key.

**Note:** Riot's developer policy doesn't allow using several keys to get around rate limits. This is here to test
the fetcher with a larger budget, not for everyday use.

## Measured
- New tests: a rejected extra key is set aside while the others carry on; extra keys are added, listed masked, kept
  free of repeats and removed (settings file and server API).
- The client, settings, scheduler and server tests pass; the web type check and build pass.
