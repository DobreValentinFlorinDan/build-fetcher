# Irelia Companion 0.14.1

**Steadier and lighter on the processor.** A newer Electron with the Node.js fix for an occasional crash, a Storage card that opens at once, and about a quarter of the processor time to compress the Riot API cache.

The installer is per-user (no admin rights), lets you choose the install folder, and creates **Irelia Companion** shortcuts in the Start Menu and on the desktop. It isn't code-signed yet, so Windows SmartScreen will warn on first run: choose **More info → Run anyway**. Installing over 0.14.0 keeps your settings, API key and match data in `%APPDATA%\irelia-companion\`.

## Steadier
- **Electron 44.9.3**, with Node.js 24.22. The Node.js of 0.14.0 (24.21) crashed now and then as one of the app's threads ended. On Windows that was an access violation, and the app restarted its middleware a few seconds later. Threads end after every evaluation and when champ select starts. 24.22 fixed the use-after-frees in that path. In the tests on Windows, 24.21 crashed in about 3 % of full runs, and 24.22 in none of 55.

## Lighter on the processor
- **Compression at zstd level 9** instead of 15, for the Riot API cache and the database's timelines:
  - **About a quarter of the processor time:** on Riot-shaped test data (synthetic), a match takes 9.5 ms instead of 37 ms, and a timeline 21 ms instead of 137 ms. Each fetched game costs about 30 ms of one core instead of about 175 ms. Converting a large cache from an earlier version takes about a quarter of the time.
  - **A little more disk:** a match is 7.6 KB instead of 6.6 KB, and a timeline 47 KB instead of 41 KB. That is still 35 % and 21 % smaller than the gzip files before 0.14.0.
  - **What 0.14.0 wrote stays as it is,** and reads the same. Decoding is as fast as before.
- **The Storage card opens at once.** The size of the API cache now comes from a small index, not from reading every cached response:
  - On a 3 GB cache (synthetic), that took 0.6 s, or 6.6 s with a cold disk, and the app's middleware waited meanwhile. Now it takes about 30 ms.
  - Trimming the cache of old patches lists its matches and timelines in half the time (1.3 s → 0.65 s).
  - The fetching thread builds the index once, 30 s after the app starts, and not during a game. It takes about 8 MB per 240,000 cached responses (a few seconds to build on a large cache).
- **The conversion of earlier versions' cache files reads them folder by folder** as it goes, instead of listing hundreds of thousands of them in memory first.

## Also
- The cache's schema version in its meta table is 2 once the index is built. Nothing else in the files changed.
