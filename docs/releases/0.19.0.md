## Backup
- **Where:** in the Data tab, **Backup** → **Choose a backup folder…**, for example a folder inside your Google Drive. The pool is saved there as a ZIP once a week (the 3 newest are kept), and **Back up now** does it on request. It runs in the background: the app, fetching and the live game carry on.
- **What's in it:** the pool's games and the one-tricks and mains it follows. Other players' IDs are left out. It can be large (gigabytes), so the first save takes a while.
- **Another computer:** point its app at the same folder. It offers the newest backup made on a different computer and imports it only when you click **Import**. **Import a backup ZIP…** takes any backup file by hand. Importing only adds games that computer doesn't have; nothing is replaced, and it asks first because the pool's builds then include them.
- **Safe for a synced folder:** a backup is written under a temporary name and renamed when finished, so Google Drive never uploads half a file.

## Data tab
- **No more jumping while fetching:** the pacing text appears in a place reserved for it, so nothing below it moves.
- **Hide details:** a switch hides the log lines (last event, your account, the per-server lines, the GPU log). They keep working underneath.

## Use GPU: the weighted sums stay on the processor
- A GPU version of the evaluation's weighted sums was prepared, but on a real laptop card it made a full evaluation crawl: to stay **identical to the last digit**, one GPU thread adds each option's games in order, about 9 ms a pass (an estimate) against 1.3 ms on one processor thread (measured), and every evaluation thread waits its turn on the card. It is off. **Use GPU** works out the similarities on the card as in 0.13.0.

## Evaluate builds: more threads in the app
- **Why it was slow:** in the app, every thread shares one 4 GB memory area. The evaluation counted too much per thread against it, so on large pools it often ran on one thread, and a one-thread run never measured itself, so the next one stayed there.
- **No more sleeping through it:** the computer now stays awake while an evaluation you started runs, as it does while fetching (Settings → Keep the computer awake while fetching or evaluating, on by default). Before, an idle PC could go to sleep a few minutes in and the evaluation stood still until you came back; its elapsed time and estimate counted the sleep.
- **Now:** each thread holds less (the stored rows are dropped once the baselines are built, repeated game texts are kept once), and the plan counts only what really goes into the shared area. On about 150,000 games, expect 2–3 threads instead of 1 (an estimate; the Data tab and the log line `[eval] threads:` show the real number). The report stays **identical to the last digit**.

## Also
- Data and policy are unchanged: Riot API and Data Dragon only, nothing leaves your PC unless you choose a backup folder, and no new dependencies.
- **Removed before release:** a per-player data set mode (builds from one player's games only) was prepared for 0.18.0, which was never published. It was dropped: one player's games are too few to build from.
