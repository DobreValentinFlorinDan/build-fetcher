## Why
A full evaluation compares every held-out game with every stored game, so its time grows with the square of the games: 32 minutes at 82,000 games, an estimated hour and a half at 150,000. This release is the first part of the plan in `docs/EVAL-SCALING.md`.

## Time by step
- Every evaluation report, in the app and from `npm run eval:builds`, ends with **Time by step**: each step's time and share, then by kind (a step's folds added up), largest first. The middleware's log shows the three largest (`[eval] time: …`).
- Nothing else in the report changes: on the same games, it is 0.19.0's to the last digit.

## Grouped drafts: a trial
- **What:** the stored drafts are put into up to 1,024 groups of similar drafts. Each held-out game is compared with the groups instead of every stored game. The exact matchup layer stays per game.
- **Why it is sound:** this is binned kernel estimation, a standard method (Silverman 1982, Fan & Marron 1994). Its error comes from the groups' spread against the bandwidth, and the report gives that spread.
- **Measured on synthetic data:**
  - At 150,000 drafts, one comparison takes 0.25 ms instead of 7.8 ms (31× faster).
  - The best option matched the exact one in 93 % of drafts, and every time it led by more than half a point. The ones that differed were near-ties.
  - A whole evaluation of 6,000 synthetic games took 59 % less time, with the same verdict and lift.
  - Real drafts vary more than synthetic ones, so **your games decide**.
- **Try it on your games:** close the app (or leave it idle), then run `npm run eval:builds -- --compare-grouped`. It runs a full exact evaluation, then the grouped trial on the same games, and saves the two side by side (time, every verdict, the lifts) as `eval-compare-….txt` in `%APPDATA%\irelia-companion\evals`.
- **Nothing in the app changes:** the trial is saved as `eval-grouped-…`. The app's verdicts, its quick updates and the evaluation history stay the exact evaluation's. Champ select and the overlay never use grouping.
- **What's next:** if the comparison meets the limits in `docs/EVAL-SCALING.md`, the next release makes grouping the default for full evaluations. Those limits: every verdict the same, the lift within 0.1 pts, and at least 50 % faster.
