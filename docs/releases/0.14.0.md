# Irelia Companion 0.14.0

**A lighter app.** Less memory while idle, less processor and memory during your games, and much less disk. Your builds don't change: the evaluation report is identical to 0.13.0's to the last digit.

## During your games (Settings → While you play)
- **Pause fetching during games**, on by default:
  - In champ select and in game, no Riot API requests and no database writes, so League has the network, the disk and the processor.
  - Fetching resumes when the game ends, and your new game is fetched then. The Data tab says "Paused for the game".
  - Keep-awake follows fetching, so it lets go during the game.
- **Lower priority:** during champ select and games the app runs at below-normal priority (its middleware, and the dashboard if it's open). Normal again after the game.
- **Memory freed when champ select starts:** every thread collects its garbage, and on Windows the app hands the memory it doesn't touch back to Windows. If that frees less than 50 MB on your computer, it isn't done again.
- **Measured in a simulated game** (94,000 synthetic games, fetching on, on Linux; Windows will differ):
  - the middleware used 5.3 % of one core, against 8.6 % with 0.13.0;
  - and 721 MB, against 824 MB;
  - collecting the garbage when it began freed 56 MB (473 → 417 MB). The working-set trim on top of that only happens on Windows, so it wasn't measured here.

## Less memory
- **The draft model holds its numbers in flat arrays:** before, one array per game and per item, plus a second flat copy of the draft part.
  - **Idle, with a 94,000-game model** (synthetic, patch memory on, measured on Linux): the middleware takes 473 MB, against 531 MB with 0.13.0.
  - **The model thread:** its heap went from 248 MB to 124 MB. The flat arrays take 59 MB outside the heap, so that's 51 MB less in all.
  - **The other processes** (the window, the GPU process, Electron itself) are the same as before.
- **Evaluate builds:** each thread takes a little less per game (9,413 bytes per game read, against 9,758 the same day on 0.13.0), so a few more threads fit. The report is identical byte for byte (54,000-game test database, 1 and 4 threads).
- **Windows:** the dashboard was already closed for real when you close it to the tray, and the overlay already exists only during a game. Both stay that way.

## Less disk
- **The Riot API cache is one file now** (`cache\riot-cache.db`), not one file per response.
  - **Better compression:** zstd with a dictionary made from your own cache. On Riot-shaped test data (synthetic), a match is 44 % smaller than with gzip (6.6 KB against 11.8 KB) and a timeline 31 % smaller (41 KB against 60 KB). Both decode as fast as before.
  - **No overhead** of hundreds of thousands of small files.
- **Timelines in the database are compressed** the same way. On the 54,000-game test database (synthetic), the database went from 686 MB to 149 MB; on a 94,000-game one, from 1,187 MB to 259 MB. Real timelines vary more than the test ones, so expect less: about a twelfth of their size (an estimate, from compressing them without a dictionary).
- **Converted in the background:** the first time you start 0.14.0, your cache files and timelines are converted while the app is idle, a batch at a time. It pauses in champ select and games.
  - **Nothing is lost:** each item is read back and compared before its old copy is deleted. A file it can't read stays where it is, and is still read as before.
  - **Progress** shows in Settings → Storage.
- **Space comes back by itself:** deleting old patches, archiving and trimming the cache now shrink the files too.
  - Databases from before 0.14.0 need one full compaction first. Settings → Storage suggests **Compact database** once the conversion is done.
  - On your data, Compact database also stores each player ID and match ID once, if the player table is most of the database and it comes out smaller (in real data the same players meet again and again). It checks every row before switching. On the synthetic test database it didn't switch, because each test player ID appears only once there.

## Slim stored data (Settings → Storage)
The one action that deletes data, and only when you click it. It never runs in champ select or a game, and fetching pauses while it runs. It waits for a running Evaluate builds or data audit, and neither starts while it runs, so the results it compares can't change meanwhile. What it deletes:
- the raw cached timelines of games older than the newest two patches, whose games the database has already captured;
- the fields of cached matches and timelines that nothing in the app reads. Each one is kept only if every capture gives the same result from the slim copy. On Riot-shaped test data, this leaves a match at 2.3 KB and a timeline at 11 KB;
- in the archive (patches older than patch memory's window), the other players' kills, items, gold and similar columns, which nothing reads once their per-champion sums are stored.

How it protects your data:
1. **Free space:** it checks there is room for a backup first, and refuses if there isn't.
2. **Backup:** a copy of the database (with its SHA-256) and the affected cache entries, in `backup-0.14.0\` in your data folder.
3. **Results before:** a quick evaluation and the builds for 200 stored drafts (the lane baseline, the draft-adjusted build and the live "Next" at five moments of each game).
4. **Slimming.**
5. **Results after:** the same again. If anything differs, it rolls back by itself and tells you what differed.

If everything is the same, it shows **"Verified: same results. Backup kept"** with two buttons:
- **Roll back:** puts everything back and checks it. Games fetched since stay.
- **Keep the slimmer data:** deletes the backup, after a confirmation that lists what could only come back by fetching it from Riot again.

If the app closes or crashes mid-way, the next start finishes the job safely: before slimming, nothing had changed; from slimming on, it rolls back.

## Also
- **Going back to 0.13.0** after the conversion is not supported: it can't read the compressed cache and timelines.
- **New endpoints:** `GET`/`POST /api/storage/slim`; `PUT /api/settings {pauseFetchingInGame}`. Details are in docs/DESKTOP.md §4.
- **No new dependencies.** koffi (from 0.13.0) is now also loaded on Windows for the working-set trim.
