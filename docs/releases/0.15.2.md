## Slim stored data
On 0.15.1 it stopped before slimming with "Worker terminated due to reaching memory limit: JS heap out of memory". Nothing was changed when that happened.

In the app, every thread shares one 4 GB memory limit, and Slim's check builds a model of its own beside the one the app keeps. Your PC measured about 1.3 GB per extra evaluation thread at 121,000 games, so the check could run out of room.

- **The check's quick evaluation runs on Slim's own thread alone.** The results are the same as on several threads.
- **Each part's leftovers are cleared before the next part starts.** On the test database (54,000 games, 30,000 of them read by the quick evaluation), Slim's thread held:

  | When | Before | After |
  |---|---|---|
  | Starting the model build | 318 MB | 12 MB |
  | Starting the drafts | 502 MB | 213 MB |

  At your size it should be about 4 times as much (estimate).
- **The app's model thread lets go of what it keeps for requests when Slim starts.** That's mainly the games behind the lane builds, about 130 MB at 54,000 games; it keeps the model itself.
- **The slimming threads together stay within 1.5 GB of the shared limit.** That's 4 threads where up to 8 ran before.
- **The cost:** the check took 286 s before and 363 s after on the test database, and it runs twice per Slim.
- **If a thread still stops, the note now says which one.** It reads either "its thread stopped: …" or "A helper thread stopped: …".

## Evaluate builds
The report is the same byte for byte. Each lane build (one per lane and opponent) is now worked out once per fold and handed to every thread, and the training games are checked once instead of once per opponent. Before, each thread built the ones its own games needed, mostly the same ones.

Measured on the test database with its lane opponents spread over 120 champions, on 2 threads:

| | 0.15.1 | 0.15.2 |
|---|---|---|
| Evaluate builds | 837 s | 673 s (−20%) |
| Choosing the settings | 212 s | 74 s |

Your first evaluation on 0.15.1 (121,000 games, 2 threads, 30 min) spent about 57 s per settings round beyond its games (an estimate), likely much of it these lane builds.
