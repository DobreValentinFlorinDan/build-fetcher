# Irelia Companion 0.11.0

**Evaluate builds now runs on every core your computer has, as far as its free memory allows.** The results are the same to the last digit. The Data tab shows your processor and memory, and how many threads the evaluation will use. **The overlay now shows the starting items to buy** (Doran's Blade or Long Sword, potions).

## Evaluate builds on every core
- **Your computer:** under **Evaluate builds** (Data tab), a line now names your processor, how many threads it runs at once, your memory and how much of it is available. It also says how many threads the next evaluation will use and how much memory each one takes, e.g. "Evaluate builds would run on 12 threads, each beyond the first taking about 1.3 GB (an estimate)".
- **How much faster:**
  - On the 54,000-game test database, on a 4-core machine: 12.2 min on one thread, 4.5 min on four (2.7×), with the report the same byte for byte.
  - About a sixth of the work still runs on one thread: reading the games and fitting the game-state model. So more cores help less and less. On 8 threads, expect about 3.8× faster than one; on 16, about 4.7× (estimates).
- **Memory:**
  - Each extra thread holds its own copy of your games while it works: about 1.2 GB at 54,000 games, growing with the games. The evaluation peaked at 4.9 GB on four threads there, against 1.3 GB on one.
  - It only starts as many threads as fit in the memory available at that moment. 15 % of your memory (at least 1.5 GB) is always left free, so nothing spills to disk.
  - If free memory runs low while it runs (another program starts), it stops one thread at a time until it's fine again. Their work goes to the first thread; nothing is lost.
  - Each evaluation measures what a thread took on your computer, and the next one plans with that.
- **Champ select or a game:** the extra threads stop at once and give their memory back to the game. An evaluation you started finishes on one thread; an automatic one stops, as before.
- **While it runs:** the bar says how many threads it is using ("step 6 of 22 · 12 threads"). The time estimate allows for them. The finished report's line says how long it took and on how many threads.
- **Same results:** each thread takes the next batch of games as soon as it is free. The first thread then adds up every game's result in the original order, so every sum is the same as on one thread. The tests check this with 2 and 3 threads, with a thread killed mid-run, and with champ select starting mid-run.

## Overlay: what to buy first
- **Above the build order:** the overlay now shows the build's starting items with their counts, e.g. Doran's Blade + Health Potion ×2. These are the same items as the Build tab's Starting Items card.
- **In a game:**
  - It is titled **Buy first** until you own one of its items, or until 1:30.
  - It then turns grey with ✓, and it goes at 3:00.
  - Until you've bought the start, the "With 500g: …" best-buy line waits, so the overlay doesn't suggest boots with your starting gold.

## Also
- `npm run eval:builds -- --threads N` runs the evaluation on N threads (the same report); by default it uses as many as the app would.
- The live-game simulator (`POST /api/dev/simulate-live`) now starts you with 500 gold and an empty inventory, and buys the start at 0:20, as in a real game.
