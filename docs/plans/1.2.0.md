# Work brief: Build Fetcher 1.2.0, item advice that learns from enemy builds

This brief organizes the work for 1.2.0. Each workstream says what to change, where, and what "done" means.

## Goal (from the user)
- **Overlay:** the next item worth buying, given:
  - the items you have;
  - the enemy's items;
  - your gold.
- **Model:** learns this from every stored game (each player's buys and the enemy's items at that moment) and keeps
  learning as games arrive: one game in, learned, the next one fetched.

## Decisions already made (do not reopen)
- **Learn from both teams, not only winners.** Winners alone teach what is popular, not what wins.
- **Keep the per-game extracts (1–3 KB) after training.**
  - Raw timelines are already never stored.
  - Match ids stay in `seen`, so no game is fetched twice.
  - Clean-up keeps deleting the oldest games under the disk budget.
- **Several ranked options, never a single instruction.** No pop-ups.

## Rules that apply to every workstream
- **Riot policy, read on 2026-11-25:**
  - General policies (last updated May 29, 2025, https://developer.riotgames.com/policies/general):
    - Products "should not remove game decisions, but may highlight decisions that are important and give multiple
      choices";
    - they "should increase, and not decrease the diversity of game decisions (builds…)".
  - League game policy (https://developer.riotgames.com/docs/lol#game-policy). Unapproved:
    - "Apps that dictate player decisions";
    - "Products may not provide any game-session-specific information that would be previously unknown to the
      player".
  - **Consequences:**
    - Use only what the player can see: your own gold, and every player's items as the Tab scoreboard shows them.
    - Never show or estimate the enemy's gold.
    - Show 3 options with reasons.
- Vanguard-safe: only the Live Client Data API in game.
- No API key in code, logs, tests or errors.
- Measure everything (results, disk, time, memory) and state what was not verified.

## Workstream 1: the model sees the enemy's items (`crates/learn`)
1. **`Situation`.** Add `enemy_items: Vec<i64>`: the enemy team's completed items owned at that minute.
   - Samples: built from each enemy's purchase log (`owned_at`).
   - Live: built from `LiveContext.enemy_items`.
2. **Enemy-build tags,** from Data Dragon:
   - armor, magic resist, healing (life steal, omnivamp), anti-heal;
   - AP, AD and crit;
   - health (tanks).
   Counted per enemy team, scaled 0–1.
3. **New feature families,** in a new weight region appended after the pair region, starting at zero:
   - each enemy item;
   - each enemy tag;
   - **my item × enemy tag**: this is what lets "Void Staff against magic resist" be learned;
   - **champion-role × enemy tag**.
   Because the region starts at zero, an existing checkpoint predicts exactly as before. It loads padded, nothing is
   lost and nobody waits for a fresh model.
4. **Done when:**
   - A synthetic set with a planted "item X wins more against armor stacking" effect is learned (test).
   - Old checkpoints load and predict identically (test).
   - The checkpoint size is measured.

## Workstream 2: continuous learning (`crates/learn/src/learner.rs`, `crates/server/src/wire_learn.rs`)
1. **A draft model in memory.**
   - **`absorb`:** reads whatever new games exist (from one up), trains the draft on them plus replay, and adds them
     to the replay buffer and contexts. It runs whenever you're not in champ select or a game, even while the PC is
     in use; each call is short.
2. **`check`:** the existing guardrail, run on the draft against the model in force.
   - **When:** every 150 learned games, or after the first 2,000 for the very first model.
   - **Accepted:** the draft becomes the served model; the store cursor advances.
   - **Rejected:** the draft keeps learning and is checked again later. After 8 rejections in a row it is reset to
     the model in force (logged).
   - **Calibration:** fitted on held-out records gathered since the last accepted model, so it has enough matches.
3. **Restart:** the draft is lost on restart; games since the last accepted model are learned again (nothing lost).
4. **Heavy work stays idle-only:** re-scoring and clean-up. Clean-up runs at most once an hour.
5. **Status:** the Model page says "Learning continuously: N games since vX; next check at 150".
6. **Done when:**
   - Tests cover absorb, check, accept, reject, the reset after 8, and a restart.
   - The time per game and per check is measured.

## Workstream 3: overlay with gold (`crates/core/src/build.rs`, `recommend.rs`, `web/src/Overlay.tsx`)
1. **`LiveAdvice.buys`** (serde default), one entry per next-buy option:
   - the gold still missing, counting components already owned;
   - the best affordable component to buy now;
   - a reason from the enemy's items ("2 enemies build magic resist").
2. **Ranking:** by the model with your items and the enemy's items (workstream 1). Gold only says what you can buy
   now; it never hides an option.
3. **Overlay:** 3 options, best first. Each shows "buy now", or "650 short: Blasting Wand (850) now", and its reason.
   Counters stay.
4. **Done when:** the advice changes with enemy items and gold in tests, and the web build and tests pass.

## Workstream 4: more timelines for all champions (settings)
- **Settings → Fetching:** a "Timelines for other champions" choice: 10%, 25%, 50% or 100%.
- **Default for new installs:** 25%.
- **Measure:** the request cost per game at each share.
