# Build Fetcher 1.5.1

**1.5.1 fixes fetching that sent about 1,400 requests an hour and brought in no games. A request Riot refused was
retried every 5 seconds, forever, by both fetchers. The Fetching page now also shows the fetcher's last error.**

## Fixed
- **0 matches / hour with 1,000+ requests / hour.** Riot encrypts player ids (puuids) per API key's account. A player
  id seen with one key, or the one the League client gives for you, gets a 400 from a key of another account. The
  fetcher treated that as a passing error. It waited 5 seconds and asked for the same player again, so both fetchers
  stayed on one player ("Now: my games") and spent their requests there.
  - **Now:** a request for a player is tried on each key until one can read the id. When none can, the player leaves
    the pool and the fetcher moves on. A player is marked as checked before the request, so a failure is never retried
    at once.
  - **Your own games:** when your puuid can't be read, the fetcher looks up your Riot ID with the keys in use and
    fetches your games with that. In a game, you are now recognized by your puuid or your Riot ID, so games fetched
    with either key count as yours.
- **Errors were invisible.** The fetcher's errors went only to an internal log.
  - **Now:** the Fetching page shows the newest error from the last hour.

## Measured
- Rust tests and the web type check pass.
- New tests: a player id is tried on each key and reported once neither can read it. Unreadable players are asked
  for once instead of every 5 seconds. Your Riot ID is looked up when your puuid can't be read, your games are stored
  as yours, and games keep coming in (this test fails on 1.5.0).
