# Build Fetcher 1.0.0

**Build Fetcher recommends a build for any champion in any role: runes, summoner spells, skill order, starting items, item path, boots and late-game swaps. It learns from every new high-elo match it fetches, runs only on your PC, and shows the evidence behind each choice.**

The installer is per user, with no admin rights. Settings, data and logs live in `%APPDATA%\build-fetcher\`, and the uninstaller keeps that folder. Build Fetcher installs next to Irelia Companion and never writes to Irelia Companion's folder or install. The installer isn't code-signed yet, so Windows SmartScreen warns on first run: choose **More info → Run anyway**.

## First run
1. **API key.** If Irelia Companion has a key, click **Use the same key as Irelia Companion**. Only that value is copied, from a read-only open of its `config.json`; nothing there is changed. Otherwise paste a key from https://developer.riotgames.com. A key Riot rejects (401/403) is reported in Settings, with a link to the portal.
2. **Region.** Choose your region; EUN1, EUW1 and KR are fetched by default. Fetching then starts in the background.

## What it does
- **Champ select.** It detects your champion and role and shows the build at once, updating as picks come in. **Import** puts the rune page and an item set into the League client for any champion. It only replaces pages and sets it created itself (named "Build Fetcher…"). Other players' names are never read or shown.
- **In game.** The overlay shows several next-buy and counter-item options, re-ranked from the live game (your items, the enemies' items, levels, CS, kills and objectives). Every option shows its evidence. Nothing pops up and there are no timers. Riot's policy asks apps to highlight choices, not make them.
- **Evidence everywhere.** Each option shows:
  - plain games and wins;
  - the sample size;
  - the shrunk win rate and the win probability added;
  - what it is based on: the matchup, the enemy's damage profile, the lane or the champion.

  Thin data are flagged, and fall back from matchup to profile to lane to champion.
- **Two tiers.**
  - **Tier A, your pool:** your top 5 champions, the ones you add in Settings, and any champion played 3 times this patch. These get detailed records and the learned model, aware of the draft and the game state.
  - **Tier B, every other champion and role:** counts by patch, rank, lane opponent and enemy damage profile, ready the moment you lock in.

## Data
- **Source:** ranked solo/duo on Summoner's Rift, Master+ on EUN1, EUW1 and KR. A champion-role pair with too few games widens to Diamond automatically. Your own EUN1 games come first, and count more in the model.
- **Dropped:** remakes; games with an AFK or leaver; games whose roles can't be assigned with confidence; malformed answers. Every drop is counted by reason on the Fetching page.
- **One record per match,** deduplicated across players and regions. Patch and hotfix come from the game version, and recent patches and higher rank weigh more.
- **Shared key.** Build Fetcher and Irelia Companion use one key and one rate limit. Build Fetcher reads Riot's rate-limit count headers on every answer, so it never passes the key's limit, even while Irelia Companion is fetching. The Fetching page shows when another app uses the key.
- **Pauses** in champ select and in game.
- **Disk:**
  - 2 GB by default, adjustable in Settings → Storage.
  - Raw API answers are never kept.
  - After each training cycle the app keeps the checkpoints, the counts, a fixed validation sample and the records still being learned from, and deletes the rest. It trims the oldest patches while over the budget, compacts the database, and logs the bytes freed.

## Learning
- **Incremental.** It retrains as games arrive, with warm-started mini-batches, only while the PC is idle, and never in champ select or a game.
- **Two models.** Step 1 is a logistic model per champion-role, shrunk toward a global model. Step 2 is a small shared network with champion, item, rune, summoner and skill-order embeddings. A step is used only when it beats the one before on held-out games.
- **Guardrails.** Every update is checked on 4,000 held-out games: log loss, Brier score, and calibration error for 0-10, 10-20, 20-30 and 30+ minutes. An update that makes any of them worse is rejected and the previous checkpoint is kept. Checkpoints are versioned, Settings → Model rolls back to an earlier one in one click, and the log says what each update changed.
- **Calibration.** A temperature over game time keeps the model's confidence honest. It is fitted on records held out from training, and changes only when the evidence is statistically clear.
- **Deterministic on the CPU** for the same data, whatever the number of threads.
- **GPU (NVIDIA, off by default).** Settings → GPU moves the training and evaluation forward pass and the draft-similarity sums onto the card. Its results are checked against the CPU before use and on a sample while it runs; any mismatch falls back to the CPU. It takes effect after a restart.

## Measured
On Linux, 4 cores, synthetic match-v5 data (details and commands in `docs/MEASUREMENTS.md`):

| What | Result |
|---|---|
| Storage | about 1 KB of database per counted game (50,000 games: 46 MB) |
| Ingestion | about 2,400 games/s |
| Clean-up | 26 MB freed in 0.8 s when trimming to a budget |
| Model quality (20,000 matches) | baseline log loss 0.690 → step 1 0.4971 → step 1 + 2 0.4970; Brier 0.248 → 0.1682 → 0.1681 |
| Planted effects | recovered: a rune page against one opponent, a rushed item, an item against magic damage, a thin champion flagged |
| Training | an incremental update of 2,000 games takes 5-8 s on 4 CPU threads |
| Recommendations | 7 ms (tier A) and 0.5 ms (tier B) |
| App memory | 48 MB idle, headless, with the real database and learner |

## Not verified before release
- **Real Riot data.** No real API key was used in development. Requests and matches per day, record sizes and model quality on real games will be measured on the first day of real fetching.
- **A real GPU.** The GPU code was tested against the CPU on an interpreter of its kernel, not on a graphics card. It is off by default.
- **Windows behaviour.** CI builds, tests and packages on Windows. The overlay on a running game, the tray and the League client import were tried only in simulation.
