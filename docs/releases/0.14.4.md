## Slim stored data
- **Fixed: the slimming read the whole backup again for every game.**
  - The step "Slimming the cached matches and timelines" looked up each game's backup entries without the index, so SQLite read the entire backup, stored data included, for each game.
  - The time grew with the square of the number of games. With 2,000 games, that already doubled the step's time. With about 226,000 games, it would have taken days.
  - Each game is now two index lookups.
- **The slimming runs on several cores.**
  - Each game (decompressing, the captures' check, compressing again) goes to helper threads, 50 games at a time.
  - It uses every core but the one writing, as much as the free memory allows (up to 384 MB each), and at most 8.
  - One thread writes, in one transaction per 50 games.
  - The written data is byte for byte the same on any number of threads (tested on 1 and 3).
- **Measured on 2,000 Riot-shaped games (synthetic, Linux, 4 cores):**

  | Version | Time per game |
  |---|---|
  | 0.14.3 | 61.5 ms |
  | 0.14.4, one thread | 29.0 ms |
  | 0.14.4, three threads | 11.0 ms |

- **At about 226,000 games (estimate):** about 1.8 h on one core, and roughly 20 to 40 min with 4 to 8 cores, depending on the processor and the disk. The card shows the time left from your PC's own pace.
- **A run started in 0.14.3 or earlier is still slimming the old way.** Quitting the app (tray → Quit) rolls it back at the next start, with its progress on the splash. Then start it again in 0.14.4.
