# Build Fetcher 1.2.2

**1.2.2 lets continuous learning get past its first model: updates are now corrected for overconfidence before the
safety check judges them.**

## Fixed
- **The model never got past v000001.**
  - **What happened:** every update was rejected on calibration in the 10–30 minute windows (0.10–0.17 against
    0.03–0.08), although it predicted far better (log loss 0.62–0.65 against 0.684). After 8 rejections it was
    thrown away and learning started over.
  - **Cause:** the step that corrects too-extreme probabilities needs at least 250 held-out matches. In continuous
    learning each update gathered its own and lost them when it was thrown away: at most about 174. So the
    correction never ran, and no update could pass.
  - **Now:** the held-out matches go into one pool, the newest 2,000, kept across checks, rejections and resets.
    It is refilled from the stored games when Build Fetcher starts. Every check corrects the update with it first,
    then runs the same strict safety check as before.

## What to expect
- **Within the first hour:** the learning log should show "calibration pool: N held-out matches from the store",
  and later checks should report a calibration temperature other than 1.000.
- **If the corrected updates pass,** the Model page shows v000002 and later versions, and the in-game advice uses
  them.
